Fast Evaluation Path

Validate the core before term discussions.

The buyer path is intentionally core-first: build the engine, run the tests, inspect the determinism evidence, and only then decide how deeply to assess the broader modules.

Step A

Build + run tests

Compile the current release candidate and confirm the baseline in your own environment.

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
Step B

Run determinism proof

Use the included proof tooling to validate repeatability and rollback-oriented confidence.

tools\run_determinism_proof.bat build
# logs emit into proof/RUNS/
Step C

Review buyer docs

Hand architecture, provenance, and commercial docs to engineering, legal, and exec stakeholders in parallel.
