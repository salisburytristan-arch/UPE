## Requirement Coverage (Buyer Checklist)

- Complete private source-code repositories: included via full source zip.
- Commit history, branches, tags, and releases: included via git bundle and metadata report.
- Copyright ownership in original code: documented in rights/ownership references.
- Project name, logo, and branding: documented with referenced website and media assets.
- Domain name, when applicable: CNAME reference is documented, but parent domain registration/hosting/payment accounts are excluded by default.
- Documentation and architecture materials: included in source archive.
- Tests, benchmarks, examples, and demos: included in source archive.
- Build and deployment scripts: included in source archive.
- Website and promotional materials: included in source archive and mapped in manifest.
- Associated datasets or tooling legally owned: mapped in manifest (tooling and data assets).
- Related accounts legally transferable: documented as transfer checklist and schedule.
- Defined transition-support period: specified in transition terms.
- Rights to modify/commercialize/rebrand/sublicense/discontinue: specified in transition terms for transfer agreement use.

## Notes

- This package does not itself execute legal transfer. Final transfer and license rights are activated only through signed definitive agreements.
- If additional repositories or external account exports are part of deal scope, append them to `TRANSFER_MANIFEST.md` and regenerate checksums.
- The current domain/website scope is static files only. No standalone domain registration, BearPack parent domain, hosting account, payment account, or dedicated operating website is included by default.
- See `KNOWN_BLOCKERS_AND_DISCLOSURES.md` for sale-blocking technical disclosures that must be fixed or explicitly accepted by the buyer.
